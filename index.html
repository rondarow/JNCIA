Junos OS Fundamentals

Control Plane vs Data Plane

Junos OS maintains a strict separation between control and data planes:

Control Plane (Routing Engine)

  • Manages routing protocols and system configuration
  • Runs routing protocols daemon (rpd)
  • Processes management traffic
  • Maintains routing tables

Data Plane (Packet Forwarding Engine)

  • Handles packet forwarding at high speeds
  • Uses forwarding tables from RE
  • Processes transit traffic
  • Implemented in ASICs for performance

Key Daemons

Daemon Function
rpd (Routing Protocol Daemon) Manages routing protocols (OSPF, BGP, IS-IS, RIP)
mgd (Management Daemon) Handles CLI and user management sessions
chassisd (Chassis Daemon) Manages hardware components and status
dfwd (Firewall Daemon) Processes firewall filters and security policies

CLI Prompts

  • Superuser prompt: username@hostname#
  • Operational mode: username@hostname>
  • Configuration mode: username@hostname# edit (shows [edit] in prompt)

Configuration Basics

Configuration Management

Junos uses a candidate configuration model where changes must be committed to take effect.

Configuration Workflow

Enter Configuration Mode
configure
Make Configuration Changes
Validate Configuration
commit check
Commit Configuration
commit
Configuration Active

Configuration Files

File Purpose
juniper.conf.gz Active running configuration
rescue.conf.gz Rescue configuration for recovery
rollback files (0-49) Previous configurations (rollback 0 = active)

Essential Configuration Commands

  • configure - Enter configuration mode
  • commit - Apply candidate configuration
  • rollback n - Load previous configuration (n=0-49)
  • load merge - Add configuration from file
  • load override - Replace candidate configuration
  • save <filename> - Save candidate to file
  • request system configuration rescue save - Save rescue config
  • request system zeroize - Factory reset device

User Interfaces

CLI (Command Line Interface)

  • Primary management method
  • Hierarchical structure
  • Tab key for auto-completion
  • Extensive help system (?)
  • Operational and configuration modes

J-Web (Web Interface)

  • Graphical user interface
  • Point-and-click configuration
  • Real-time monitoring
  • Useful for beginners

NETCONF (XML-based API)

  • Programmatic interface
  • XML-based configuration
  • SSH transport (port 830)
  • Automation-friendly

CLI Tips and Tricks

  • Use show configuration | display set to output configuration as set commands
  • Pipe commands with | for filtering (e.g., show interfaces | match up)
  • Use run command to execute operational commands from configuration mode
  • Save time with command abbreviations (e.g., sh int for show interfaces)

Monitoring & Maintenance

Interface Monitoring Commands

  • show interfaces terse - Brief interface status
  • show interfaces extensive - Detailed interface statistics
  • monitor interface <interface-name> - Real-time interface monitoring

System Monitoring Commands

  • show system alarms - Check for hardware/software issues
  • show chassis hardware - View hardware inventory
  • show system processes - Monitor system processes
  • show system storage - Check storage utilization

Troubleshooting Commands

  • clear arp - Clear ARP cache
  • ping <destination> - Test connectivity
  • traceroute <destination> - Trace network path
  • test ping <source> <destination> - Ping from specific source
  • request support information - Collect troubleshooting data

Common Monitoring Scenarios

Interface Issues: Use show interfaces extensive to check for errors, drops, and flapping.

Routing Problems: Use show route and show route protocol <protocol> to verify routes.

Hardware Problems: Use show chassis hardware and show system alarms to identify issues.

Routing Fundamentals

Routing Tables

Table Purpose
inet.0 IPv4 unicast routes
inet6.0 IPv6 unicast routes
inet.1 IPv4 multicast routes
mpls.0 MPLS label switching information

Default Route Preferences

Lower values are more preferred:

Route Type Preference
Directly connected 0
Static 5
OSPF internal 10
IS-IS Level 1 15
IS-IS Level 2 18
RIP 100
OSPF external 150
BGP 170

Routing Protocol Types

Distance-Vector (RIP)

  • Uses hop count as metric
  • Periodic full routing table updates
  • Simple but less efficient
  • Maximum 15 hops

Link-State (OSPF, IS-IS)

  • Uses SPF/Dijkstra algorithm
  • Event-triggered updates
  • Faster convergence
  • More complex but scalable

Path-Vector (BGP)

  • Uses path attributes for decision
  • Policy-based routing
  • Used for inter-domain routing
  • TCP-based (port 179)

Routing Policy Actions

  • accept - Allow route to be used/exported
  • reject - Deny route from being used/exported

OSI Model Reference

Layer Name Function Examples
L1 Physical Physical connection Cables, connectors
L2 Data Link Frame delivery MAC addresses, switches
L3 Network Logical addressing IP addresses, routers
L4 Transport End-to-end delivery TCP, UDP
L7 Application Network services HTTP, DNS, SSH

Transport Protocols

TCP (Transmission Control Protocol)

  • Connection-oriented
  • Reliable, in-order delivery
  • Flow control and congestion control
  • Examples: HTTP, HTTPS, SSH, FTP

UDP (User Datagram Protocol)

  • Connectionless
  • Faster, no guarantee of delivery
  • No flow or congestion control
  • Examples: DNS, VoIP, video streaming

Junos Firewall Cheatsheet

Firewall Filter Overview

Junos firewall filters are stateless packet filters that can be applied to:

  • Interfaces (input/output)
  • Loopback interface (for control plane protection)
  • Specific routing instances

Firewall Filter Structure

  • set firewall family inet filter FILTER_NAME term TERM_NAME from <match-conditions>
  • set firewall family inet filter FILTER_NAME term TERM_NAME then <action>
  • set interfaces <interface-name> unit <unit-number> family inet filter input FILTER_NAME

Common Match Conditions

Match Condition Syntax Example Description
Source/Destination IP source-address 192.168.1.0/24 Matches source IP range
Protocol protocol tcp Matches TCP packets
Port destination-port 22 Matches destination port
ICMP Type icmp-type echo-request Matches ping requests
TCP Flags tcp-flags "(syn & !ack)" Matches TCP SYN packets
Interface interface ge-0/0/0.0 Matches packets on specific interface

Firewall Actions

Action Syntax Description
Accept then accept Allow packet to pass through
Discard then discard Silently drop packet
Reject then reject Drop packet and send ICMP unreachable
Count then count COUNTER_NAME Count matching packets
Log then log Log matching packets
Syslog then syslog Send matching packets to syslog
Next Term then next term Continue to next term in filter

Firewall Filter Examples

Basic SSH Filter (Allow SSH from specific network)

  • set firewall family inet filter SSH-FILTER term ALLOW-SSH from source-address 10.1.1.0/24
  • set firewall family inet filter SSH-FILTER term ALLOW-SSH from protocol tcp
  • set firewall family inet filter SSH-FILTER term ALLOW-SSH from destination-port 22
  • set firewall family inet filter SSH-FILTER term ALLOW-SSH then accept
  • set firewall family inet filter SSH-FILTER term DENY-ALL then discard

ICMP Filter (Allow ping but not other ICMP)

  • set firewall family inet filter ICMP-FILTER term ALLOW-PING from protocol icmp
  • set firewall family inet filter ICMP-FILTER term ALLOW-PING from icmp-type echo-request
  • set firewall family inet filter ICMP-FILTER term ALLOW-PING then accept
  • set firewall family inet filter ICMP-FILTER term DENY-OTHER-ICMP from protocol icmp
  • set firewall family inet filter ICMP-FILTER term DENY-OTHER-ICMP then discard
  • set firewall family inet filter ICMP-FILTER term ALLOW-OTHER then accept

Policers and Rate Limiting

Policers allow you to rate-limit traffic:

  • set firewall policer LIMIT-1M if-exceeding bandwidth-limit 1m
  • set firewall policer LIMIT-1M if-exceeding burst-size-limit 100k
  • set firewall policer LIMIT-1M then discard
  • set firewall filter MY-FILTER term LIMIT-TRAFFIC then policer LIMIT-1M

Monitoring Firewall Filters

  • show firewall - Show firewall filter statistics
  • show firewall filter FILTER_NAME - Show specific filter stats
  • show firewall log - Show firewall log entries
  • clear firewall filter FILTER_NAME - Clear filter counters
  • monitor traffic interface <interface-name> - Real-time traffic monitoring

Best Practices

  • Always include an explicit default action (accept or discard) as the last term
  • Order terms from most specific to most general
  • Use meaningful term names for easier troubleshooting
  • Test filters with commit confirmed to avoid locking yourself out
  • Use counters and logging during implementation for verification
